# 项目功能方案

## 一、定位

项目是资料的**轻量聚合标签**，不是管理工具。

用户告诉系统"这些资料属于 IoT 项目"，AI 就知道优先从这里找。项目管理有 Jira、飞书项目，不必重复。AuraCommand 的项目极轻：只有名字、聚合视图、AI 上下文感知。

## 二、核心原则

1. **最轻**——项目就是名字，没有状态/颜色/描述/甘特图
2. **多对多**——一份资料可以属于多个项目，一个项目包含多种资料
3. **不建 projects 表**——项目名是字符串，不需要独立实体表
4. **不建 items 统一索引**——直接引用原始表 id，不做映射层
5. **不建 item_links**——V1 不做 supports/references 等显式关系，项目归属就是关联
6. **AI 自动感知**——选了项目后，AI 自动知道项目全貌，不需要手动关联

## 三、数据模型

### 3.1 唯一新增表：project_items

```sql
CREATE TABLE IF NOT EXISTS project_items (
  project_name TEXT NOT NULL,
  item_type TEXT NOT NULL,
  item_id TEXT NOT NULL,
  PRIMARY KEY (project_name, item_type, item_id)
);
```

字段说明：

| 字段 | 说明 |
|---|---|
| `project_name` | 项目名，纯字符串，如"IoT反控巡检" |
| `item_type` | 资料类型：`note` / `clip` / `task` / `kb_file` |
| `item_id` | 原始表中的 id，直接引用 notes/clips/tasks/file_metadata 的 id |

联合主键保证同一资料不会重复归入同一项目。

一条资料可以归入多个项目，只需多插一行：

```
('大屏可视化', 'kb_file', '通信协议说明.pdf的id')
('IoT反控巡检', 'kb_file', '通信协议说明.pdf的id')
```

### 3.2 现有表的兼容处理

`notes` 表已有 `project TEXT` 字段（旧数据）。处理方式：

- **新数据**：归入项目时写入 `project_items`，不再写 `notes.project`
- **旧数据**：启动时执行一次迁移，把 `notes.project` 中有值的记录同步到 `project_items`
- **`notes.project` 字段保留不删**，RAG 的 space 标签仍然读取它，迁移后两者保持一致

### 3.3 不建的表

| 表 | 原因 |
|---|---|
| `projects` | 项目名是字符串，不需要独立实体。3-5 个项目不值得建表 |
| `items` | 直接引用原表 id + type，不需要映射层，省掉同步维护成本 |
| `item_links` | V1 不做显式关系类型（supports/references 等），项目归属就是关联 |
| `link_suggestions` | V1 不做 AI 推荐关系 |
| `item_chunks` | 现有 RAG 已有分块，不另建 |

## 四、IPC 设计

### 4.1 三个 IPC

#### add-to-project

```ts
入参：{
  projectName: string,
  itemType: 'note' | 'clip' | 'task' | 'kb_file',
  itemId: string
}
出参：{ success: boolean }
```

INSERT OR IGNORE 到 project_items。如果 item_type 为 'note'，同时更新 notes.project 字段保持兼容。

#### remove-from-project

```ts
入参：{
  projectName: string,
  itemType: 'note' | 'clip' | 'task' | 'kb_file',
  itemId: string
}
出参：{ success: boolean }
```

DELETE FROM project_items。如果 item_type 为 'note'，同时检查 notes.project 是否需要清空。

#### list-project-items

```ts
入参：{
  projectName: string
}
出参：{
  notes: { id: string, title: string, type: string, updated_at: string }[],
  clips: { id: string, content: string, ocr_text: string, created_at: number }[],
  tasks: { id: string, title: string, status: string, priority: number, due_date: string | null }[],
  kb_files: { id: string, title: string, file_name: string, updated_at: string }[]
}
```

实现逻辑：

1. 从 project_items 查出该项目所有 (item_type, item_id)
2. 按 item_type 分组
3. 到原表批量取详情

### 4.2 辅助查询

项目列表从现有数据动态提取，不需要 projects 表：

```sql
SELECT DISTINCT project_name FROM project_items ORDER BY project_name
```

## 五、AI 上下文

### 5.1 项目概览注入

用户在项目筛选下聊天时，system prompt 自动注入项目资料概览：

```
【当前项目：IoT反控巡检】
便签(2): 反控流程设计、设备通信要点
文档(1): IoT线上反控巡检系统UI原型设计概览
截图(2): UI原型首页、设备状态面板
待办(1): ☐ 完成反控接口联调
知识库(1): 通信协议说明.pdf
```

实现：chat handler 收到 projectName 参数 → 调 list-project-items → 按类型分组拼摘要 → 注入 system prompt。

### 5.2 RAG space 标签

现有 RAG 已通过 `notes.project` 生成 space 标签（如 `[IoT巡检]`）。迁移后 notes.project 与 project_items 保持一致，space 标签继续生效。

## 六、UI 设计

### 6.1 项目筛选器（嵌入现有页面）

在 DeskPage 和 TasksPage 的侧边栏上方加项目下拉：

```
┌─────────────────────────┐
│ 📁 项目: IoT反控巡检  ▾ │  ← 下拉选择器
├─────────────────────────┤
│ 📝 便签  📄 文档  🖷截图 │
│                         │
│  反控流程设计文档         │  ← 只显示该项目的资料
│  设备通信协议说明         │
│  UI原型首页截图           │
│  ☐ 完成反控接口联调       │
└─────────────────────────┘
```

选了项目后：
- notes 过滤：查 project_items 中该项目 + type='note' 的 id 列表，过滤列表
- clips 过滤：查 project_items 中该项目 + type='clip' 的 id 列表，过滤列表
- tasks 过滤：查 project_items 中该项目 + type='task' 的 id 列表，过滤列表

清空项目筛选 → 回到全局视图。

### 6.2 归入项目

各资料类型提供"归入项目"操作：

| 资料类型 | 入口 | 操作 |
|---|---|---|
| 便签/文档 | 侧边栏列表右键菜单 | "归入项目" → 下拉选项目 |
| 截图 | 截图详情区 | "归入项目" → 下拉选项目 |
| 待办 | 待办详情面板 | "归入项目" → 下拉选项目 |
| 知识库文件 | 文件列表右键菜单 | "归入项目" → 下拉选项目 |

归入操作支持多选项目，一个文件可以同时归入多个项目。

### 6.3 不做的 UI

- ❌ 独立项目 Tab + 项目详情页（V1 项目只有 3-5 个，筛选器够用）
- ❌ 关系面板（V1 不做显式关系类型）
- ❌ 拖拽归入（交互成本高，V1 不做）
- ❌ 项目状态/颜色/描述（项目名本身就是标识）

## 七、数据流

```
用户创建便签"反控流程设计"
  → 保存到 notes 表
  → 可选：归入项目"IoT巡检" → INSERT INTO project_items

用户打开项目筛选"IoT巡检"
  → list-project-items → 拿到所有资料 id
  → 按类型过滤各列表

用户在项目筛选下聊天
  → list-project-items → 拼概览
  → 注入 system prompt 的【当前项目资料概览】段
  → RAG 搜索时 space 标签自然命中同项目资料

用户归入知识库文件到项目
  → INSERT INTO project_items ('IoT巡检', 'kb_file', '文件id')
  → 同一文件可再归入"大屏可视化"
```

## 八、迁移策略

### 8.1 旧数据迁移

`notes.project` 字段中已有项目归属数据，需要一次性同步：

```sql
INSERT OR IGNORE INTO project_items (project_name, item_type, item_id)
SELECT project, 'note', id FROM notes WHERE project IS NOT NULL AND project != ''
```

### 8.2 新数据写入

新创建资料归入项目时，同时写 project_items 和 notes.project（仅 note 类型），保持两者一致。

## 九、实施顺序

| 步骤 | 内容 | 依赖 |
|---|---|---|
| 1 | 建 project_items 表 + 旧数据迁移 | 无 |
| 2 | 3 个 IPC（add-to-project / remove-from-project / list-project-items） | 步骤1 |
| 3 | DeskPage 项目下拉筛选器 | 步骤2 |
| 4 | 各资料类型"归入项目"操作 | 步骤2 |
| 5 | TasksPage 项目筛选器 | 步骤2 |
| 6 | AI 上下文注入项目概览 | 步骤2 |

每步独立可用，步骤 1-2 是纯数据层，步骤 3-6 是 UI 层。

## 十、V2 预留

以下能力 V1 不做，但设计上不阻碍未来扩展：

| 能力 | 触发条件 | 扩展方式 |
|---|---|---|
| 项目状态/颜色/描述 | 项目超过 10 个，需要视觉区分 | 新建 projects 表，project_items 加 project_id 外键 |
| 显式关系（supports/references 等） | 需要精确表达"截图是待办的证据" | 新建 item_links 表，直接引用 (item_type, item_id) |
| AI 推荐关联 | 手动关联成本高 | 新建 link_suggestions 表 |
| 统一索引层 | 资料超过 500 条，跨表查询慢 | 新建 items 表做映射 |
